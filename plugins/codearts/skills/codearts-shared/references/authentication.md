# 鉴权：AK/SK 与 IAM 令牌

> 本文件由 `skills/codearts-shared/SKILL.md` 引用：凭证被判无效、或不确定该用哪种鉴权方式时读它。


实测这类部署的 APIGW 两种都支持，**AK/SK 可以直接用**。关键是别被「没带凭证」的报错误导：

| 发出的请求 | 网关返回 | 说明 |
|------------|----------|------|
| 不带任何凭证 | `APIGW.0301 ... x-auth-token not found` | 只是「没有凭证」，不代表只支持令牌 |
| 带 AK/SK 签名（AK 不存在） | `APIGW.0301 ... ak <AK> not exist` | 签名格式已被接受，只是这个 AK 查不到 → 真实 AK/SK 可用 |
| 带 AK/SK 签名（AK 存在但无权限） | 403 | 凭证有效，去 IAM 补权限 |

判定方法：用 `codearts probe <服务域名>` 看返回。它不带凭证，所以只能区分「要求凭证」与「地址不对」，
无法区分 AK/SK 与令牌；要确认 AK/SK 是否被接受，直接用真实凭证跑一次只读命令
（`codearts project list`）看返回即可，**不要为了试探去填假 AK**——那会覆盖已保存的可用凭证。

被拒绝时（401/403）不需要靠猜：CLI 会把能判断的都写进报错里，见
[troubleshooting.md](troubleshooting.md) 的「判断密钥到底对不对」一节——
包括你配置的密钥的长度与形状、以及**这组密钥上次成功是什么时候**。
两者都只能让 CLI 与用户确认「是不是同一把、是不是粘全了」，读不到密钥本身；
报错文本里网关回显的 AK 也会被替换成 `<redacted>`。

鉴权方式选择：

- `aksk`（默认推荐）：填 AK/SK，逐请求签名。
- `token`：部署只发放令牌时使用。可填 IAM 终端节点 + 账号名 + 用户名 + 密码由 CLI 自动换取并缓存；
  若 IAM 取 token 接口不可达，也可以直接粘贴一个 `X-Auth-Token`
  （从已登录的 CodeArts 控制台开发者工具里任意请求头上复制，约 24 小时有效，不能自动续期）。

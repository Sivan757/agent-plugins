# JPA to Jimmer Migration

## Entity Conversion

### JPA Entity (Java class) → Jimmer Entity (Kotlin interface)

```java
// JPA (Java)
@Entity
@Table(name = "book")
public class Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String name;

    private int edition;

    @Column(precision = 10, scale = 2)
    private BigDecimal price;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "store_id")
    private BookStore store;

    @ManyToMany
    @JoinTable(
        name = "book_author_mapping",
        joinColumns = @JoinColumn(name = "book_id"),
        inverseJoinColumns = @JoinColumn(name = "author_id")
    )
    private List<Author> authors = new ArrayList<>();

    // Constructor, getters, setters, equals, hashCode...
}
```

```kotlin
// Jimmer (Kotlin)
@Entity
interface Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    val id: Long

    @Key
    val name: String

    @Key
    val edition: Int

    val price: BigDecimal

    @ManyToOne
    val store: BookStore?

    @ManyToMany
    @JoinTable(
        name = "BOOK_AUTHOR_MAPPING",
        joinColumnName = "BOOK_ID",
        inverseJoinColumnName = "AUTHOR_ID"
    )
    val authors: List<Author>
}
```

### Key Differences

| Aspect | JPA | Jimmer |
|---|---|---|
| Entity type | Class | Interface |
| Mutability | Mutable (`var`, setters) | Immutable (`val` only) |
| ID type | Boxed `Long` (nullable) | Primitive `Long` |
| Fetch strategy | `FetchType.LAZY/EAGER` | Object Fetcher (explicit) |
| Business key | No native support | `@Key` annotation |
| N+1 problem | Manual JPQL/EntityGraph | Auto-optimized fetcher |
| Creation | `new Book()` + setters | `Book { }` DSL (Draft) |

### Step-by-Step Conversion

1. **Change `class` to `interface`** and remove all method bodies
2. **Replace `var` fields with `val` properties** — Jimmer entities are immutable
3. **Remove `@Column`** — Jimmer infers column names from property names
4. **Remove `FetchType`** — no lazy/eager; use object fetchers instead
5. **Add `@Key`** on business/natural key fields for UPSERT support
6. **Make optional associations nullable** (`BookStore?` not `BookStore`)
7. **Remove constructors, getters, setters** — generated by KSP
8. **Remove `equals`/`hashCode`/`toString`** — generated automatically

## Repository Conversion

### JPA Repository → Jimmer KRepository

```java
// JPA (Java)
public interface BookRepository extends JpaRepository<Book, Long> {
    List<Book> findByNameContaining(String name);
    @Query("SELECT b FROM Book b WHERE b.store.name = :storeName")
    List<Book> findByStoreName(@Param("storeName") String storeName);
}
```

```kotlin
// Jimmer (Kotlin)
interface BookRepository : KRepository<Book, Long> {
    fun findByName(
        name: String? = null,
        pageable: Pageable,
        fetcher: Fetcher<Book>? = null
    ): Page<Book>
}
```

Key differences:
- `KRepository` replaces `JpaRepository`
- Fetcher parameter controls loading depth (replaces JPQL joins and EntityGraphs)
- Default parameter values enable dynamic queries
- Complex queries use type-safe DSL instead of JPQL strings

## Service Layer Conversion

### JPQL/Criteria API → Jimmer DSL

```java
// JPA (Java) — JPQL string, no compile-time safety
@Query("SELECT b FROM Book b " +
       "JOIN b.store s " +
       "WHERE (:name IS NULL OR b.name LIKE %:name%) " +
       "AND (:storeName IS NULL OR s.name = :storeName)")
Page<Book> search(@Param("name") String name,
                  @Param("storeName") String storeName,
                  Pageable pageable);
```

```kotlin
// Jimmer (Kotlin) — type-safe DSL with dynamic predicates
fun search(name: String?, storeName: String?, pageable: Pageable): Page<Book> =
    sqlClient.createQuery(Book::class) {
        name?.let { where(table.name ilike it) }
        storeName?.let { where(table.store.name eq it) }
        orderBy(table.name.asc())
        select(table.fetch(SIMPLE_FETCHER))
    }.fetchPage(pageable.pageNumber, pageable.pageSize)
```
